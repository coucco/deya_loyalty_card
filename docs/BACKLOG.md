## Сеть касс (до пилота)
- [ ] **DNS на кассах**: тестовая касса не находит адрес сервера (`UnknownHostException`), временно — строка в `/etc/hosts`. На боевых кассах проверить `getent hosts loyalty.<домен>` и `curl https://loyalty.<домен>/healthz`; прописать рабочий DNS (роутер магазина или 77.88.8.8) или hosts с автозапуском (`/opt/bootlocal.sh`).

## Информационная безопасность
До реальных клиентов (дёшево, сильно снижает риск):
- [ ] **Сервер**: вход по SSH только по ключу, запрет пароля и root-входа по паролю; `ufw` — открыты только 22/80/443; `unattended-upgrades`; `fail2ban`.
- [ ] **Админка только с доверенных адресов**: ограничить `/admin` и `/api/admin` по IP офиса/VPN в Caddy (или второй пароль basic-auth).
- [ ] **API касс только с IP гипермаркета**: ограничить `/api/v1/*` по внешнему IP магазина — украденный ключ `pk_…` не сработает снаружи.
- [ ] **Лимиты против накрутки**: максимум баллов за чек / за день по карте / по точке, оповещение об аномалиях (сейчас сервер верит данным чека от плагина с верным ключом).
- [ ] **Код входа 6 цифр + дневной лимит кодов на номер** (сейчас 4 цифры, 5 попыток, 5 кодов/час — для целевого подбора за сутки маловато).
- [ ] **Копии БД вне сервера, зашифрованные и неудаляемые**: хранилище с блокировкой удаления (object lock / версии) и отдельными ключами доступа; иначе взломщик с root удалит и базу, и копии.
- [ ] **Шифрование диска / копий**: шифрованный диск VPS (если хостинг даёт), копии — `rclone crypt` или `age`.
