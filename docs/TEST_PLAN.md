# План внедрения и тестирования: тестовая касса и тестовый сервер Set10

Идём этапами: следующий начинаем, когда выполнен критерий предыдущего. Этапы 0–3 — минимум для начисления; 4–7 — пластик, списание, 3 этаж, поддержка; 8 — пилот на боевой кассе.

**Окружение:** тестовая касса Set Retail 10 **10.5.3.0**, боевые **10.4.27.0**. Тестовые карты Set10: **999000000000001 – 999000000000010** (15 цифр): 001–007 — виртуальные (приложение), 008–010 — пластиковые. Установка и настройки плагина — `set10-bonus-plugin/dist/INSTALL.md`.

## Что внедряем

| Артефакт | Где | Куда |
|---|---|---|
| `DeyaBonusAccrualPlugin.jar` 1.2.0 (плагин лояльности + плагин карт, манифест внутри) | `set10-bonus-plugin/dist/` | сервер Set10 и тестовая касса |
| `metainf.xml` (копия манифеста) | `set10-bonus-plugin/dist/` | только для проверки |
| Сервер лояльности | `docker compose up -d --build`, `.env` из `.env.example` (`CARD_ISSUE_MODE=pool`, СМС-провайдер, `BACKUP_DIR`) | VPS в РФ с HTTPS, доступный с тестовой кассы |
| Ключ точки «Гипермаркет» | админка → «Новый ключ» | настройка плагина `api.key` |

## Этап 2. Касса узнаёт карту, «цена 3»
| # | Проверка | Критерий |
|---|---|---|
| 2.1 | Сканер кассы читает **QR** из приложения; если не читает — «Показать штрихкод» | карта в чеке как карта Set10 нужного типа |
| 2.2 | Товар с «ценой 3» + карта | цена 3 применилась; без карты — обычная цена |

| **Критерий** | | карта стабильно опознаётся, «цена 3» работает (`card.mode=internal`) |

### Этап 2b. Режим `card.mode=external` (кнопка «оплатить бонусами») — главный вопрос
| # | Проверка | Критерий / решение |
|---|---|---|
| 2b.1 | Переключить `card.mode=external`, перезапустить кассу, добавить карту в чек | на экране карты баланс «Баллы ДЕЯ», держатель — ID профиля |
| 2b.2 | Товар с «ценой 3» + карта | **если цена 3 применилась** — режим `external` годится; **если нет** — попробовать акцию Set10 на категорию карт (`card.category.guid`) или порядок поиска «внутренние карты первыми»; не получилось — вернуть `internal` (списание только автоматическое) |
| 2b.3 | Сервер выключен, карта в чек | карта добавляется без баланса, «цена 3» работает, чек продаётся |

## Этап 3. Начисление (главное)
| # | Сценарий | Критерий |
|---|---|---|
| 3.1 | Плагины положены, зарегистрированы, касса перезапущена | «Бонусы ТРЦ Дея» и «Карты ДЕЯ» в списках, в логе нет ошибок загрузки |
| 3.2 | Чек с картой приложения | в приложении «+N баллов» за ≤ 5 с; N = Σ(позиции после скидок) × % |
| 3.3 | Чек с «ценой 3» | баллы от суммы после цены 3; в логе (`log.payload`) у позиции видно `discount`/`discounts` — **записать, как Set10 передаёт цену 3** |
| 3.4 | Чек без карты / с чужой картой | запросов нет |
| 3.5 | Сервер выключен → чек → сервер включён | кассир не ждёт; чек доезжает сам, баллы 1 раз |
| 3.6 | Неверный `api.key` → чек → исправить | в логе 401, после исправления доезжает |
| 3.7 | Возврат (полный и частичный) | баллы уменьшились пропорционально |
| 3.8 | X-отчёт между подытогом и оплатой | начисление и списание проходят (ссылка на чек не зависит от номера чека) |
| 3.9 | Админка → «Расхождений журнала» | 0 |
| **Критерий** | | 20+ чеков без двойных начислений, касса не тормозит |

## Этап 4. Пластиковые карты и активация на кассе
| # | Сценарий | Критерий |
|---|---|---|
| 4.1 | Прокатать/отсканировать пластик 008 | карта в чеке, «цена 3» есть |
| 4.2 | Кассиру предлагается «Карта не активирована» → «Позже» → покупка | чек продан; баллы на гостевом профиле (админка: «пластик без привязки») |
| 4.3 | Следующая покупка с 008 → «Активировать» → телефон покупателя (без приложения) → СМС → код | «Карта активирована. Профиль …»; баллы сохранились; согласия записаны каналом `pos_sms` |
| 4.4 | Неверный код, «Отмена» на любом шаге, сервер выключен | касса продолжает чек, без зависаний |
| 4.5 | Клиент из 4.3 входит в приложение тем же телефоном | тот же ID профиля и баллы, выдана виртуальная карта, пластик виден |
| 4.6 | Пластик 009 активировать на телефон, у которого уже есть профиль с пластиком 008 (утеря) | предупреждение «прежняя карта ****0008 будет заблокирована»; баллы 009 перешли в профиль; 008 больше не начисляет |
| 4.7 | Привязка 010 в приложении (номер + код активации) | баллы перенесены |
| 4.8 | «Инфо по карте» на кассе | профиль, баланс, статус |
| 4.9 | Поиск клиента по телефону на кассе | карта найдена и добавлена в чек (в режиме `internal` — **проверить**, добавляет ли Set10 найденную плагином карту как свою) |
| **Критерий** | | все перестановки «пластик ↔ приложение» дают один профиль и общий баланс |

## Этап 5. Списание в гипермаркете
Предварительно: «Гипермаркет» → «Макс. оплата баллами» = 5 %; `redeem.enabled=да`, `redeem.mode=both`.

| # | Сценарий | Критерий |
|---|---|---|
| 5.1 | Авто: клиент включил «Списывать баллы в гипермаркете»; чек 1000 ₽ без цены 3 | на подытоге «Оплата баллами: 50 б.», скидка 50 ₽ |
| 5.2 | Авто: позиции по цене 3 | на них скидки баллами нет |
| 5.3 | Повторный подытог / отмена чека | резерв не удваивается / снимается |
| 5.4 | Кнопка кассира (`external`): «оплатить бонусами» → потолок 5 % → ввести 30 | скидка 30 ₽, баллы списаны один раз (после пробития не повторно) |
| 5.5 | Кнопка, затем аннулирование чека | баллы вернулись (rollback) |
| 5.6 | Возврат чека со списанием | списанные баллы вернулись, начисленные отменены |
| 5.7 | Клиент выключил переключатель / сервер недоступен | авто-списания нет, чек без задержки > `redeem.timeout` |
| 5.8 | Тип скидки (`redeem.discount.type`), печать чека, ФД | чек корректен для бухгалтерии/ОФД |

## Риски и допущения

| Риск / допущение | Как проверяем / что делаем |
|---|---|
| В режиме `external` не работает «цена 3» | этап 2b; категория карт или остаёмся в `internal` (без кнопки, с автосписанием) |
| Поиск по телефону в режиме `internal`: Set10 может не добавить карту, найденную плагином, как свою | 4.9; иначе поиск по телефону — только в `external` или через «Инфо по карте» |
| Формы кассы (активация) из плагина карт на 10.4/10.5 ведут себя иначе | 4.3–4.4 на тесте и пилоте; выключатель `card.activation` |
| Сканеры 1D не читают QR | штрихкод Code128 в приложении |
| Set10 передаёт «цену 3» не скидкой | 3.3; флаг «запрет оплаты бонусами» на товарах |
| Касса не вызывает `cancelDiscount` | резерв истекает сам (`POS_HOLD_TTL_SEC`), при пробитии без скидки снимается сразу |
| СМС не доходят | активация на кассе невозможна → клиент активирует в приложении; карта при этом работает (гостевой профиль) |
| Тест 10.5.3.0 новее боя 10.4.27.0 | пилот на одной боевой кассе (этап 8) |
| Юридическое: тексты документов — заглушки; согласие при активации на кассе даётся сообщением кода из СМС | юрист проверяет формулировку СМС и правила; уведомление РКН; сервер в РФ |
