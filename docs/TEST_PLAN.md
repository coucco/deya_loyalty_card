# План внедрения и тестирования на тестовой кассе и тестовом сервере Set10

Идём этапами: каждый следующий начинаем, только когда выполнен критерий прохождения предыдущего. Этапы 1–3 — минимум для запуска начисления; 4–6 можно проверять параллельно позже.

## Что нужно и что внедряем

| Артефакт | Где взять | Куда |
|---|---|---|
| `DeyaBonusAccrualPlugin.jar` | `set10-bonus-plugin/dist/` (или `cd set10-bonus-plugin && gradle build` → `build/libs/`). **Перед сборкой для кассы впишите реальный e-mail/телефон поставщика в `gradle.properties`** (Set10 требует их в манифесте jar) | сервер Set10: `/var/lib/jboss/plugins/` (Linux) или `{диск}:\SetRetail10\plugins\`; тестовая касса: `/storage/crystal-cash/plugins/` |
| Манифест плагина `metainf.xml` (+ `strings_ru/en.xml`) | уже **внутри jar** (`src/main/resources/`), проверен по `docs/metainf.xsd` из SDK | отдельно класть не нужно |
| Сервер лояльности | `docker compose up -d --build` по `docs/DEPLOY.md`, `.env` из `.env.example` (`CARD_ISSUE_MODE=pool`) | VPS в РФ с HTTPS, доступный **с тестовой кассы** |
| Ключ точки «Гипермаркет» | админка → «Новый ключ» | настройка плагина `api.key` |
| 10 тестовых карт Set10 | от вас | админка → «Пул карт»: например 7 как «виртуальные (QR)», 3 как «пластиковые» (`номер;код`) |

Настройки плагина в Set10 («Интеграция → Внешние процессинги» → «Бонусы ТРЦ Дея»):

| Настройка | Тест | Бой |
|---|---|---|
| `server.url` | `https://<домен>/api/v1/accruals` | то же |
| `api.key` | ключ точки «Гипермаркет» | новый ключ |
| `point.id` | `hypermarket` | `hypermarket` |
| `card.prefix` | префикс(ы) тестовых карт, через запятую | префиксы боевых диапазонов |
| `redeem.enabled` | `false` до этапа 5 | по решению |
| `log.payload` | **`true`** (видим JSON чека в логе кассы) | `false` |
| остальное | по умолчанию | по умолчанию |

В «порядке применения провайдеров лояльности» наш плагин — **последним** (после скидок Set10).

## Этапы, проверки, критерии

Версии: тестовая касса **10.5.3.0**, боевые **10.4.27.0** (обе с `onReceiptFiscalized`/`cancelDiscount`). Тест новее боя → этап 7 (пилот на одной боевой кассе) обязателен. Тестовые карты Set10: **9990000000000001–9990000000000010** (сверить длину номера в Set10); предлагаемое деление: 1–7 виртуальные, 8–10 пластиковые. Комплект для установки и настройки — `set10-bonus-plugin/dist/INSTALL.md`.

### Этап 0. Предусловия (½ дня)
| # | Проверка | Критерий |
|---|---|---|
| 0.1 | Версия Set Retail 10 на тестовой кассе и сервере | 10.2.x+ с поддержкой плагинов `LoyaltyPlugin`; для `onReceiptFiscalized` нужна касса 10.2.71+/API 0.0.46+ (на старших тоже работает через устаревший метод) |
| 0.2 | С тестовой кассы `curl https://<домен>/healthz` (или браузер) | `{"ok":true}`; если ошибка SSL — импортировать корневой сертификат в Java кассы |
| 0.3 | Автотесты локально: `make test`, `python3 e2e/plugin_live.py` | все зелёные |

### Этап 1. Регистрация и выдача карты из пула
| # | Проверка | Критерий |
|---|---|---|
| 1.1 | Загрузить 10 номеров в «Пул карт» | «Добавлено: 10», «свободны» = 10 (по типам) |
| 1.2 | Регистрация с телефона: без обязательных галочек кнопка неактивна; ссылки открывают документы | согласия в журнале (`consents`), рассылки — только если отмечено |
| 1.3 | Профиль → номер карты | это номер из пула (первый свободный) |
| 1.4 | Пул пуст → регистрация | клиент создан, «Карта готовится»; после загрузки номеров карта появляется сама |
| **Критерий этапа** | | 3 тестовых аккаунта получили 3 карты из пула, номера совпадают с картами Set10 |

### Этап 2. Касса узнаёт карту и даёт «цену 3» (плагин ещё не нужен!)
| # | Проверка | Критерий |
|---|---|---|
| 2.1 | Сканер кассы читает **QR** из приложения | карта добавилась в чек как карта Set10 нужного типа |
| 2.2 | Если сканер 1D и QR не читает → в приложении «Показать штрихкод» | карта добавилась (Code128) |
| 2.3 | Товар с «ценой 3» + карта | цена 3 применилась; без карты — обычная цена |
| 2.4 | Яркость/размер экрана, разные телефоны (Android/iPhone) | читается с 1–2 попыток |
| **Критерий** | | QR **или** штрихкод стабильно опознаётся, «цена 3» работает. Если нет — это настройка Set10 (тип/диапазон карт, сканер), не наш код |

### Этап 3. Плагин: начисление (главное)
| # | Сценарий | Критерий |
|---|---|---|
| 3.1 | Плагин положен на сервер и кассу, зарегистрирован, настройки дошли, касса перезапущена | «Бонусы ТРЦ Дея» в «Внешних процессингах», в логе кассы нет ошибок загрузки |
| 3.2 | Чек с картой приложения, наличные | в приложении «+N баллов» за ≤ 5 с; N = Σ(суммы позиций после скидок) × % ÷ 100 |
| 3.3 | Чек с «ценой 3» | баллы от суммы **после** цены 3; в логе (`log.payload`) у позиции видно `discount`/`discounts` — **записать, как Set10 передаёт цену 3** (нужно для этапа 5) |
| 3.4 | Чек без карты / с чужой картой | запросов нет |
| 3.5 | Сервер выключен (`docker compose stop app`) → чек → сервер включён | кассир не ждёт и не видит ошибок; чек доезжает сам (засечь интервал повторов кассы), баллы 1 раз |
| 3.6 | Неверный `api.key` → чек → исправить ключ | в логе 401, после исправления чек доезжает |
| 3.7 | Возврат по чеку (полный и частичный) | баллы уменьшились пропорционально |
| 3.8 | `enabled=false` | запросов нет, касса работает |
| 3.9 | Админка → «Сверка журнала» | 0 расхождений |
| **Критерий** | | 3.2–3.9 пройдены на 20+ чеках, ни одного двойного начисления, касса не тормозит |

### Этап 4. Пластиковые карты
| # | Сценарий | Критерий |
|---|---|---|
| 4.1 | Прокатать тестовую карту (полоса `;номер?`) / отсканировать её штрихкод | Set10 добавил карту, «цена 3» есть |
| 4.2 | Покупка по непривязанной карте | на сервере гостевой счёт с баллами (админка → клиенты «пластик без привязки») |
| 4.3 | Приложение → «Привязать пластиковую карту», неверный код → верный | ошибка → привязка, баллы перенесены |
| 4.4 | Повторная привязка той же карты другим телефоном | отказ |
| 4.5 | Перестановки: (а) пластик → покупки → регистрация → привязка; (б) регистрация → покупка по QR → привязка пластика → покупка по пластику | один счёт, баланс = сумма всех начислений; в приложении обе карты |
| 4.6 | Привязать вторую пластиковую карту | вопрос «Заменить?»; после замены старая на кассе не начисляет (422 в логе) |
| **Критерий** | | карта читается кассой и баллы корректно переходят при привязке |

### Этап 5. Списание в гипермаркете (`redeem.enabled=true`)
Предварительно: админка → «Гипермаркет» → «Макс. оплата баллами» = 5 %; при необходимости список акций «цены 3»; клиент включил «Списывать баллы в гипермаркете».

| # | Сценарий | Критерий |
|---|---|---|
| 5.1 | Чек 1000 ₽ без цены 3, баланс ≥ 50 | на подытоге сообщение «Оплата баллами: 50 б.», скидка 50 ₽ |
| 5.2 | Чек с позициями по цене 3 | на них скидка баллами не даётся |
| 5.3 | Повторный подытог (назад к товарам → снова подытог) | скидка та же, баллы не резервируются дважды |
| 5.4 | Отмена чека после подытога | резерв снят (баланс «доступно» восстановился) |
| 5.5 | Пробитие | списание и начисление (от суммы после списания) в истории клиента |
| 5.6 | Возврат такого чека | списанные баллы вернулись, начисленные отменены |
| 5.7 | Клиент выключил переключатель / сервер недоступен | чек без списания, без задержки > `redeem.timeout` |
| 5.8 | Проверить, принимает ли касса тип скидки `SUM`; если бухгалтерия требует «скидку бонусами» — `redeem.discount.type=BONUSES` | чек печатается корректно, ФД проходит |
| **Критерий** | | 5.1–5.8 на 20+ чеках, расхождений журнала 0 |

### Этап 7. Пилот → бой
Одна боевая касса 1–3 дня (`log.payload=false`), ежедневно: сверка журнала, выборочно 10 чеков вручную. Затем все кассы.

## Риски и допущения

| Риск / допущение | Как проверяем / что делаем |
|---|---|
| Сканеры гипермаркета 1D и не читают QR | штрихкод Code128 в приложении (этап 2.2) |
| Set10 передаёт «цену 3» не скидкой, а заменой цены | смотрим JSON в логе (3.3); тогда исключаем по флагу «запрет оплаты бонусами» на товарах в Set10 |
| `cancelDiscount` не вызывается на старой кассе (API < 0.0.26) | резерв истекает сам (`POS_HOLD_TTL_SEC`, 30 мин); при пробитии без скидки сервер снимает резерв сразу |
| Касса не передаёт наш `LoyaltyResult` при фискализации | плагин помнит резерв в памяти до пробития (перезапуск кассы между подытогом и оплатой — резерв истечёт, клиент получит скидку без списания: мелкая потеря, видна в журнале) |
| Номера тестовых карт ≠ формату приложения | сервер принимает любые номера 4–32 символа; `card.prefix` плагина = префиксы ваших карт |
| HTTPS-сертификат не доверен Java кассы | этап 0.2 |
| Версия касс разная | плагин защищён от отсутствующих методов (LinkageError) — проверено в самопроверке |
| Порядок вызовов методов в вашей версии Set10 отличается от SDK | `log.payload=true` на тесте, сверяем |
| Юридическое: тексты документов — заглушки | юрист; уведомление в Роскомнадзор до сбора ПДн; сервер в РФ |
