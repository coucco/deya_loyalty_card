# ДЕЯ: как устроена система лояльности

Покупатель копит баллы в гипермаркете (кассы Set10) и тратит их в гипермаркете и на 3 этаже. Баллы считает и хранит наш сервер. Set10 узнаёт карту и даёт «цену 3», наш плагин на кассе сообщает серверу о чеках.

Модули сервера: `app.js` — все адреса API; `loyalty.js` — баллы, начисление, списание, пул карт; `profiles.js` — профиль, смена номера, слияние, активация на кассе; `auth.js` — вход по СМС, согласия; `analytics.js` — метрики; `maintenance.js` — копии БД, очистка журнала; `db.js`/`schema.sql` — база.

**Данные.** Баллы принадлежат **профилю** (неизменный ID, вход по телефону). К профилю — до 1 виртуальной карты (QR в приложении) и 1 пластиковой. Номера карт заранее заведены в Set10 и загружены в «Пул карт» админки. Журнал баллов только дописывается; баланс = сумма журнала.

| Действие кассира | Метод (кто) | Что делает наш код | Запрос на сервер |
|---|---|---|---|
| Сканирует QR / штрихкод / прокатывает карту | Set10 находит свою карту → `cardSearchFinished` (плагин карт) | если это неактивированный пластик ДЕЯ — окно «Активировать?» → телефон → код из СМС | `/pos/card/status`, `/pos/activate/start`, `/pos/activate/confirm` |
| — то же в режиме `external` | `searchCard` (плагин карт) | отдаёт кассе карту с балансом и ID профиля | `/pos/card/status` |
| Ищет клиента по телефону | `searchCardAsync` (плагин карт) | находит карту профиля | `/pos/card/by-phone` |
| «Инфо по карте» | `getCardInfo` (плагин карт) | профиль, баланс, статус | `/pos/card/status` |
| Нажимает «Подытог» | Set10 считает свои акции («цена 3») → `doDiscount` (плагин лояльности, **последний**) | авто: скидка баллами, если клиент включил в приложении; кнопка: отдаёт кассе потолок списания | `/pos/redeem/reserve` или `/pos/redeem/quote` |
| Возвращается к товарам / аннулирует чек | `cancelDiscount` (плагин лояльности) | снимает резерв баллов | `/pos/redeem/cancel` |
| «Оплатить бонусами», вводит сумму (`external`) | касса снова вызывает `doDiscount`, затем `writeOff` (плагин карт) | скидка на сумму кассира, баллы списываются | `/pos/redeem/reserve` (mode=cashier), `/pos/redeem/writeoff` |
| Отменяет оплату бонусами / аннулирует | `rollback` (плагин карт) | возвращает списанные баллы | `/pos/redeem/rollback` |
| Принимает оплату | — (плагины не участвуют) | | |
| Чек пробит | `onReceiptFiscalized` → `eventReceiptFiscalized` (плагин лояльности) | отправляет чек: позиции, карта, списание | `/api/v1/accruals` |
| — сервер недоступен | касса кладёт чек в свою очередь, периодически `onSendFeedback` | повторяет отправку; дубль не начислится | `/api/v1/accruals` |
| Возврат по чеку | `onReceiptFiscalized` с типом REFUND | отменяет начисление, возвращает списанное | `/api/v1/accruals` |

Правило: при любой ошибке или без связи плагин ничего не ломает — чек продаётся как обычно, начисление доедет позже из очереди.

## 3. Встроенная лояльность Set10 и наш плагин: кто за что

По документации Crystals у Set10 есть **встроенная лояльность** (свои карты, акции, бонусные счета SetLoyalty) и **API-плагины**, чтобы подключить **внешнюю** систему лояльности — у которой свои клиенты, счета и карты. Касса вызывает плагины на тех же этапах, что и свои механизмы, и складывает результаты.

У нас разделение такое:

| Функция | Делает | Не должно делать |
|---|---|---|
| Узнать карту по QR/штрихкоду/полосе | **Set10** (карты заведены как внутренние) — в режиме `internal` | — |
| «Цена 3» по карте | **Set10** (акция на тип карты, цены из 1С) | наш плагин скидок «цены 3» не даёт |
| Бонусные баллы: начисление, баланс, списание | **наш сервер** через плагины | встроенные бонусы Set10 для этих карт **не включать** |
| Скидка баллами в чеке | **наш** `doDiscount` (сам раскладывает по позициям) | кассовую механику «бонусы setAPI» не заводить |
| Активация, телефон, баланс у кассира | **наш** плагин карт | — |

**Как настроить, чтобы не было конфликтов:**

1. **Порядок провайдеров лояльности: наш плагин последним.** Тогда в `doDiscount` «цена 3» уже применена, и сервер исключает такие позиции из списания (настраивается в админке).
2. **Не включать встроенные бонусы Set10** (бонусные счета/акции начисления бонусов) на карты ДЕЯ — иначе бонусы задвоятся и появятся две «оплаты бонусами».
3. **Не заводить механику «бонусы setAPI»** — раскладку скидки делает наш плагин; два механизма дадут двойную скидку.
4. **`card.prefix`** = префикс карт ДЕЯ (`999` на тесте) — плагин не трогает чужие карты и купоны.
5. **Режим карт `card.mode`** — единственный реальный конфликт «кто владеет картой»:

| | `internal` (по умолчанию) | `external` |
|---|---|---|
| Карту узнаёт | Set10 | наш плагин карт |
| «Цена 3» | работает | **проверить на тестовой кассе** — Set10 может не дать акцию внешней карте |
| Баланс на экране, кнопка «оплатить бонусами» | нет (баланс — «Инфо по карте») | да |
| Списание | автоматическое (по согласию клиента в приложении) | автоматическое и кнопкой |

Решение принимаем по тесту: «цена 3» в `external` работает → оставляем `external`; нет → пробуем привязать акцию к категории карт (`card.category.guid`) → не вышло → `internal`.

**6. Товары без баллов** (алкоголь, табак) — флаги Set10 «начислять бонусы» / «оплачивать бонусами» на товаре; плагин передаёт их серверу, сервер учитывает.
